# DLT technologies

## Architecture question

Which topology, privacy, identity, governance, contract and operating model meets the institutional use case?

## Design implications

- Compare single shared permissioned ledger, multiple participant ledgers and shared coordination over existing systems.
- Assess privacy/visibility, participant admission, finality rules, update authority, resilience and recovery.
- Besu, Fabric and Canton profiles have different data visibility and operational boundaries; confirm each against the chosen version and configuration.
- Public networks expose different identity, observability, fee and governance assumptions from permissioned networks.
- Avoid quantitative performance rankings without reproducible workload-specific evidence.

## Sources and caveats

See official Besu [SRC-008], Fabric [SRC-009] and Canton [SRC-010] documentation. These sources describe technologies, not independent institutional suitability or certification. Other technology profiles in the workbench are qualitative prompts and require current source verification.
