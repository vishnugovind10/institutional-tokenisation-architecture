# v0.1.0 implementation assessment

Assessment baseline: published `v0.1.0`, commit `b97ac00b8e8416159fa903d9095984408c2bb685`; reviewed 20 November 2026. This is a source and configuration audit, not a security or legal review.

## Implemented

- React + TypeScript + Vite single-page application with local component state and eight in-memory navigation views.
- Pure deterministic trade-outcome function for a fixed €5M synthetic bond trade.
- Six outcome paths: normal, cash failure, signer quorum unavailable, duplicate payment, uncertain finality and reconciliation mismatch.
- Six unit tests cover the corresponding expected outcomes.
- Static architecture, lifecycle, money, DLT, custody, decision and source content; two detailed Markdown architecture/ADR documents.
- GitHub Actions installs dependencies, runs Vitest and creates a Vite production build.
- Static Vercel production deployment. No runtime backend, authentication, database, network, payment or custody connection.

## Descriptive or illustrative

- Architecture controls select labels used in the trade narrative; they do not construct a machine-readable architecture or run design rules.
- The settlement function returns a fabricated fixed timeline and evidence IDs; it does not maintain financial balances or execute lifecycle transitions.
- The “atomic” selection changes the event wording but does not check settlement-domain compatibility.
- The “MPC 2-of-3” and “HSM” choices share the same hard-coded quorum failure behavior; no HSM service-availability state is modeled.
- Deposit mirror/omnibus, ledger topology, asset lifecycle, DLT profiles, ADRs, and source material are primarily explanatory text.
- Evidence references and transaction records are synthetic display values, not signatures, network receipts or external observations.

## Missing at baseline

- Structured architecture configuration, schema versioning, persistence, duplicate/compare, import/export or generated decision packs.
- Architecture validation findings with control IDs, status, evidence, impact, owner and remediation.
- State-bearing issuance, onboarding, subscription, position, trade, coupon, settlement and redemption domain commands.
- Separate bank-deposit, token-deposit, omnibus-backing, asset-register and token-ledger balances.
- A scenario laboratory with reproducible initial conditions and structured recovery results.
- Dedicated routes/pages, searchable research records, regulatory mapping, About page, accessibility or browser interaction checks.
- GitHub repository description/topics are empty; configured homepage is an outdated noncanonical deployment URL. Vercel project exists but is not connected to GitHub for push deployments.

## Material design weaknesses to address

- Do not infer atomic settlement from a UI selection; the modeled domain and both cash/asset mechanisms must be compatible.
- Treat cash, token, register and operational state independently. A reported payment is not automatically reconciled or legally final.
- Model HSM service availability/policy separately from MPC participant threshold.
- Treat mirror synchronization and omnibus backing/entitlement as different accounting rules.
- Keep legal finality unassessed unless sourced to governing law and the settlement scheme.
- Treat sample event IDs and statuses as simulation evidence only.

## Research and delivery gaps

- The source list is short and lacks stable source IDs, publication/effective dates, specific supported claims, limitations and confidence classification.
- European legal and standards coverage is not mapped to architecture controls; references are not legal advice.
- The DLT matrix is qualitative, but several profiles require version-specific primary-source verification before a selection assessment.
- No accessibility, route, import/export, persistence, comparison, financial invariant or browser-flow tests existed.

## Published application routes and journeys

The app is a single static SPA with no URL router. Views are switched by React state from the left navigation: Overview, Architecture, Securities lifecycle, Digital money, DLT selection, Custody & operations, Decisions, References and Simulator. A reload returns to Overview and resets simulator selections. The main journey is Overview → Simulator → change a selector → inspect a fixed result/timeline; architecture views allow component selection and details. There is no saved workspace or direct deep link to a view.

## v0.2 scope response

Preserve the working deployment and simulator presentation while introducing structured, versioned workspace state; deterministic architecture findings and lifecycle/scenario domain functions; visible design, assessment, lifecycle and scenario workspaces; local save/import/export; actual design comparison; and configuration-derived decision-pack outputs. Any external adapter remains explicitly unimplemented.
